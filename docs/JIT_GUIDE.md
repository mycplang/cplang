# JIT 编译与优化指南

> **ORC JIT v2 架构**：LLVM 18 ORC JIT 实现运行时编译，热点函数 100x 加速。

---

## 1. JIT 架构概览

### 1.1 混合 JIT 设计

CP 语言的 JIT 系统采用 **三层混合架构**：

```
┌──────────────────────────────────────────────────────────────┐
│                    HybridJIT 三层架构                         │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌──────────────────────────────────────────────────┐        │
│  │  第1层: LLVM ORC JIT (LLJIT)         最快  ← 首选 │        │
│  │  ┌────────────────────────────────────┐           │        │
│  │  │  直接内存编译，无外部进程           │           │        │
│  │  │  Lazy Compilation (按需编译)       │           │        │
│  │  │  Symbol Resolution (符号解析)       │           │        │
│  │  │  编译时间: ~5ms                     │           │        │
│  │  └────────────────────────────────────┘           │        │
│  └──────────────────────────────────────────────────┘        │
│                           │ ↓ (回退)                         │
│  ┌──────────────────────────────────────────────────┐        │
│  │  第2层: External JIT (Clang JIT)      较快  ← 回退 │        │
│  │  ┌────────────────────────────────────┐           │        │
│  │  │  通过 clang 编译 C 代码为 DLL       │           │        │
│  │  │  LoadLibrary 加载                   │           │        │
│  │  │  编译时间: ~200ms                    │           │        │
│  │  └────────────────────────────────────┘           │        │
│  └──────────────────────────────────────────────────┘        │
│                           │ ↓ (回退)                         │
│  ┌──────────────────────────────────────────────────┐        │
│  │  第3层: 字节码 VM (解释执行)         最慢 ← 保底  │        │
│  │  ┌────────────────────────────────────┐           │        │
│  │  │  Threaded-code 栈式虚拟机          │           │        │
│  │  │  支持 GC + 自动内存管理              │           │        │
│  │  │  无编译开销                         │           │        │
│  │  └────────────────────────────────────┘           │        │
│  └──────────────────────────────────────────────────┘        │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 ORC JIT 工作流程

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  CP 源码     │ →  │  AST 解析    │ →  │ LLVM IR 生成 │
│  函数 斐波那契│    │  Parser      │    │  llvm_codegen│
└──────────────┘    └──────────────┘    └──────┬───────┘
                                               │
                                               ▼
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  机器码执行  │ ←  │  ORC JIT     │ ←  │  LLVM IR     │
│  jitEntry()  │    │  LLJIT::add  │    │  Opt passes  │
└──────────────┘    └──────────────┘    └──────────────┘
       │
       ▼ (被 VM 调用)
┌──────────────────────────────────────────────────┐
│  VM 驱动：解释执行 + JIT 回调                     │
│  ┌────────────────────────────────────────────┐  │
│  │  1. 函数调用 → OP_CALL                      │  │
│  │  2. 检查 jitCompiled 标志                   │  │
│  │  3. 是 → 调用 jitEntry（直接执行机器码）      │  │
│  │  4. 否 → 解释执行字节码 + 计数               │  │
│  │  5. 超过阈值 → 触发 JIT 编译                │  │
│  └────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────┘
```

## 2. 使用方式

### 2.1 命令行用法

```bash
# 1️⃣ 热点 JIT（推荐）：函数调用超阈值后自动编译
cplang -c --hotspot 程序.cp

# 自定义热点阈值（调用次数）
cplang -c --hotspot --hotspot-threshold=50 程序.cp

# 2️⃣ 全量 JIT：启动时预编译所有函数
cplang -j 程序.cp

# 3️⃣ 交互式 REPL（默认启用 JIT）
cplang -r

# 4️⃣ AOT 编译为原生可执行文件
cplang -a 程序.cp -o 程序.exe

# 5️⃣ 优化级别
cplang -c --hotspot -O3 程序.cp    # 最高优化
cplang -c --hotspot -O0 程序.cp    # 无优化（调试用）

# 6️⃣ 查看 JIT 统计
cplang -c --hotspot -v 程序.cp
```

### 2.2 代码中标记热点

```cplang
// 无需特殊标记，JIT 自动检测热点
// 编译器自动分析频繁调用的函数

// 类型标注有助于 JIT 生成更高效的代码
函数 斐波那契(n: 整数): 整数 {
    如果 (n < 2) { 返回 n }
    返回 斐波那契(n - 1) + 斐波那契(n - 2)
}

// 全类型标注 → typed 指令 → JIT 直接编译
函数 矩阵乘法(a: 浮点[], b: 浮点[], n: 整数): 浮点[] {
    变量 result: 浮点[] = []
    // ... 编译器生成 OP_FMUL / OP_FADD 等类型化指令
    返回 result
}
```

## 3. 性能数据

### 3.1 基准测试

| 场景 | 字节码 VM | ORC JIT | 加速比 |
|------|----------|---------|--------|
| 1亿次整数循环 | 超时 (>60s) | **0.35s** | **>170x** |
| 1000万次函数调用 | 5.4s | **0.057s** | **95x** |
| 类型化函数调用 | 6.8s | **0.10s** | **65x** |
| 排序 10k 数组 | 1.2s | **0.03s** | **40x** |
| 斐波那契(35) 递归 | 2.5s | **0.05s** | **50x** |

### 3.2 编译开销

| 阶段 | 耗时 | 说明 |
|------|------|------|
| LLVM IR 生成 | ~1ms | 从 AST 生成 LLVM IR |
| IR 优化 Pass | ~2-5ms | O2 优化级别 |
| ORC JIT 编译 | ~2-10ms | 内存编译为机器码 |
| **总计** | **~5-16ms** | 首次编译延迟 |

> 编译开销仅在首次触发时发生，后续调用直接执行机器码。

## 4. 高级特性

### 4.1 LLVM IR 生成

LLVM 代码生成器（`llvm_codegen.cpp`）支持以下特性：

| 特性 | 状态 | 说明 |
|------|------|------|
| 函数定义 | ✅ | 中文/英文函数名 |
| 函数调用 | ✅ | 递归、尾调用优化 |
| 算术运算 | ✅ | 类型化指令 (OP_IADD/OP_FADD) |
| 比较运算 | ✅ | OP_ICMP/OP_FCMP |
| if/else | ✅ | LLVM phi 节点 |
| while 循环 | ✅ | 循环优化 |
| break/continue | ✅ | 正确控制流 |
| return | ✅ | 多返回点优化 |
| 变量声明 | ✅ | alloca + store |
| 数组访问 | ✅ | GEP 指针运算 |

### 4.2 符号解析与 Native 调用

ORC JIT 支持解析外部 C 符号：

```cpp
// 注册 JIT 运行时符号（orc_jit.cpp）
addSymbol("jit_printv",  reinterpret_cast<void*>(&jit_printv));
addSymbol("jit_tick",    reinterpret_cast<void*>(&jit_tick));
addSymbol("jit_strcat",  reinterpret_cast<void*>(&jit_strcat));
addSymbol("jit_table_create", reinterpret_cast<void*>(&jit_table_create));
addSymbol("jit_table_get",    reinterpret_cast<void*>(&jit_table_get));
addSymbol("jit_table_set",    reinterpret_cast<void*>(&jit_table_set));
```

**白名单机制**：JIT 编译时检查函数依赖，已知 JIT 运行时符号（`jit_*`）不会被 native call 移除算法删除。

### 4.3 类型化代码生成路径

当函数所有参数和变量都有完整类型标注时，LLVM 代码生成器跳过通用字节码路径，直接生成类型化 LLVM IR：

```cpp
// llvm_codegen.cpp 中的类型化生成
if (funcName == "tick" || funcName == "tock") {
    // → 调用 jit_tick C 函数
    llvm::Function* tickFunc = module_->getFunction("jit_tick");
    return builder_->CreateCall(tickFunc, {}, "tick");
}
```

## 5. 字节码优化

即使在 VM 解释执行模式下，字节码也会经过多层优化：

### 5.1 优化 Passes

```
┌────────────────────────────────────────────────────────┐
│  字节码优化管道                                         │
├────────────────────────────────────────────────────────┤
│                                                        │
│  1️⃣ 常量传播 (Constant Propagation)                     │
│     ┌─────────────────────────────────────────┐         │
│     │ x = 5; y = x + 3 → y = 8               │         │
│     └─────────────────────────────────────────┘         │
│                                                        │
│  2️⃣ 死代码消除 (Dead Code Elimination)                  │
│     ┌─────────────────────────────────────────┐         │
│     │ x = 1; x = 2; → x = 2  (移除第一行)      │         │
│     └─────────────────────────────────────────┘         │
│                                                        │
│  3️⃣ 窥孔优化 (Peephole Optimization)                    │
│     ┌─────────────────────────────────────────┐         │
│     │ OP_LOADINT 0 → OP_LOADNIL               │         │
│     │ OP_PUSH + OP_POP → OP_SKIP              │         │
│     └─────────────────────────────────────────┘         │
│                                                        │
│  4️⃣ 寄存器分配 (Register Allocation)                    │
│     ┌─────────────────────────────────────────┐         │
│     │ 栈变量 → VM 寄存器 (256个)               │         │
│     │ 减少内存访问，提升局部性                  │         │
│     └─────────────────────────────────────────┘         │
│                                                        │
│  5️⃣ 跳转折叠 (Jump Threading)                          │
│     ┌─────────────────────────────────────────┐         │
│     │ OP_JUMP → OP_JUMP → 直接跳转到目标       │         │
│     └─────────────────────────────────────────┘         │
│                                                        │
└────────────────────────────────────────────────────────┘
```

### 5.2 优化统计示例

```bash
$ cplang -c --hotspot -v 程序.cp

=== 字节码优化统计 ===
窥孔优化: 42 次
死指令移除: 15 条
常量传播: 28 次
寄存器分配: 256 个
节省字节: 320 B
========================
```

### 5.3 禁用优化

```bash
# 禁用所有字节码优化（调试用）
cplang -c --no-bytecode-opt 程序.cp
```

## 6. AOT 编译

### 6.1 使用方式

```bash
# 编译为原生可执行文件
cplang -a 程序.cp -o 程序.exe

# 仅生成 LLVM IR 文件
cplang --emit-llvm 程序.cp
# 输出：程序.cp.ll

# 指定优化级别
cplang -a -O3 程序.cp -o 程序.exe
cplang -a -O0 程序.cp -o 程序.exe   # 快速编译，低优化
```

### 6.2 AOT 工作流

```
程序.cp → [解析] → AST → [LLVM 代码生成] → LLVM IR
                                                  │
                                                  ▼
                                          [LLVM Optimization]
                                                  │
                                                  ▼
                                          [MCJIT/CodeGen]
                                                  │
                                                  ▼
                                          程序.exe (独立可执行)
```

### 6.3 AOT 与 JIT 对比

| 特性 | AOT | JIT |
|------|-----|-----|
| 启动时间 | 快 (原生 exe) | 慢 (需初始化 ORC) |
| 编译时机 | 预先 | 运行时 |
| 性能 | 固定 O2/O3 | 自适应优化 |
| 部署 | 单 exe | 依赖 LLVM DLL |
| 动态生成代码 | ❌ | ✅ |
| 平台独立 | ✅ (exe) | ❌ (LLVM 绑定) |

## 8. 常见问题

### 8.1 JIT 初始化失败

```
[JIT] 警告: LLVM ORC JIT 不可用，回退到字节码执行
```

**解决办法**：
1. 确保 `llvm-dev/` 目录存在且包含完整的 LLVM 库
2. 检查程序是否链接了 LLVM 库
3. 使用 `cplang -c`（纯字节码模式）作为后备

### 8.2 Native 调用被移除

如果函数调用了外部 C 函数（如 `tick()`），但该函数未被正确注册为 JIT 符号：

```
错误: 未解析的符号 jit_tick
```

**解决办法**：
1. 确认符号已在 `orc_jit.cpp` 中注册
2. 检查符号名是否拼写正确
3. 使用 `-c` 模式（纯字节码）避免 native call 移除

### 8.3 类型标注未触发 JIT

确保函数**所有**参数和变量都有类型标注：

```cplang
// ❌ 不会触发 JIT（n 无类型）
函数 求和(a: 整数, n) { ... }

// ✅ 会触发 JIT（全类型标注）
函数 求和(a: 整数, n: 整数): 整数 { ... }
```

## 9. 性能调优清单

### 9.1 启用 JIT 的最佳实践

```cplang
// ✅ 让计算密集函数全类型标注
函数 计算(n: 整数): 整数 {
    变量 result: 整数 = 0
    循环 (变量 i: 整数 = 0; i < n; i++) {
        result = result + i * i
    }
    返回 result
}

// ✅ 避免 JIT 编译小型函数（编译开销 > 执行收益）
函数 获得(x: 整数): 整数 { 返回 x * 2 }  // 太小，不值得 JIT

// ✅ 使用局部变量而非全局变量（寄存器分配更优）
// ❌ 全局：每次访问需要全局槽位查找
// ✅ 局部：寄存器分配

// ✅ 循环内避免函数调用（内联优化更好）
// ❌ 循环内调用函数阻止优化
```

### 9.2 优化级别选择

| 级别 | 编译时间 | 执行性能 | 适用场景 |
|------|---------|---------|---------|
| `-O0` | 最短 | 最慢 | 调试、快速迭代 |
| `-O1` | 较短 | 中等 | 开发测试 |
| `-O2` | 中等 | 最快 | **生产环境默认** |
| `-O3` | 最长 | 略快于O2 | 计算密集型 |
